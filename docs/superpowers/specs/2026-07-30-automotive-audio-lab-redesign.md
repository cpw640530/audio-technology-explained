# 车载声学实验室重组设计

## 目标

把现有近似椭圆座舱的示意图改为一眼可识别的整车俯视图，并通过模块切换让车辆图、信号链路和知识解释保持一致。内容既要说明部件在哪里，也要解释语音交互、声源定位、空间音频和 ANC/RNC 为什么需要这些部件。

## 交互结构

实验室使用五个按实际认知顺序排列的模块按钮：

1. 整车布局
2. 语音交互
3. 声源定位
4. 空间音频
5. ANC / RNC

默认显示“整车布局”。用户切换模块时，车辆图中的高亮部件、信号路径、图例和图下知识说明同步切换。非当前模块的部件降低视觉权重，但保留车身和座舱定位参照，避免切换后失去空间上下文。

## 车辆图形

采用整车俯视图，固定包含以下汽车视觉锚点：

- 明确标注的车头和车尾
- 四个车轮
- 前后风挡与车身外轮廓
- 四扇车门及四个独立座椅
- 方向盘、中控通道和后备厢区域

图中按模块显示顶灯麦克风阵列、ANC 误差麦、A 柱高音、仪表台中置、门板扬声器和后备厢低音炮。图形采用现有低饱和度绿色、橙色、蓝色和玫红色变量体系，不使用写实图片，以保证标注清楚且中英文文本可控。

## 模块内容

### 整车布局

显示主要麦克风、扬声器、座位和噪声源位置，解释安装位置如何影响拾音距离、声像、布线、校准和成本。图例明确区分语音麦克风、ANC 误差麦、扬声器和外部噪声源。

### 语音交互

突出当前说话座位和处理链路：

`说话人 -> 麦克风阵列 -> AEC / 降噪 / 波束形成 -> 唤醒词 / ASR -> 意图理解与安全策略 -> 车辆控制 / 语音反馈`

说明车载语音与手机语音助手的差异：系统必须结合说话座位、车速、驾驶状态、权限和安全策略决定动作是否允许执行。示例使用驾驶员调节空调和后排乘客控制娱乐系统。

### 声源定位

显示声波到达多个麦克风的路径和时间差 `Δt`，用 `Δt = d sin(θ) / c` 说明阵列如何估计方向角。明确区分：

- 声源定位负责判断谁在什么方向或座位说话。
- 波束形成负责增强目标方向并抑制其他方向。

补充强反射、通道延迟不一致、多人同时说话和音乐回放会导致定位漂移。

### 空间音频

突出 A 柱高音、门板中低音、中置、后环绕和低音炮，显示音乐、导航、告警和语音反馈的不同声像方向。说明座舱调音依赖声道映射、延迟、EQ、相位和座位补偿，并明确安全告警优先于娱乐声场。

### ANC / RNC

显示路面与轮胎噪声、参考传感器、控制器、扬声器反相信号和误差麦反馈，链路为：

`路面 / 轮胎参考 -> ANC 控制器 -> 扬声器反相信号 -> 座舱残余噪声 -> 误差麦反馈`

说明 ANC/RNC 更适合稳定低频噪声，不等同于降低音乐音量，也不适合强行抵消人声、告警和突发高频声。保留相位、延迟或环路不稳定导致压耳和轰鸣的诊断说明。

## 内容重组

主题详情中的概述改为端到端系统视角，按照“采集与定位、语音理解、回放与空间渲染、噪声控制”组织。实验室原有六张并列模块卡片改为当前模块的四段联动说明：

- 工作目标
- 处理链路
- 关键限制
- 实际例子或问题诊断

原有“唤醒错人、定位漂移、ANC 压耳或轰鸣”不再作为页面末尾的独立重复区域，而是归入对应模块。

## 响应式与可访问性

- 桌面端车辆图保持完整宽高比，模块按钮单行或自动换行。
- 小屏端模块按钮可换行，SVG 保持最小可读尺寸，不压缩文字到重叠。
- 模块按钮使用可识别的选中状态和 `aria-pressed`。
- SVG 保留 `role="img"` 和双语 `aria-label`，关键视觉含义同时存在于图下文本，避免只依赖颜色传达。
