# 会议与通信实验室实用场景化设计

## 目标

将现有以静态端到端流程图为主的会议与通信实验室，重组为以真实使用场景驱动的交互式实验室。用户切换场景时，场景图、体验说明、关键链路、观察指标和排查建议应同步变化，帮助非专业读者理解会议音频技术如何影响实际体验。

## 内容边界

实验室解释技术在会议产品中的位置、作用和排查方式，不重复展开其他实验室已有内容：

- 不重复语音增强实验室中的 AEC、NS/ANR、AGC 算法推导。
- 不重复实时音频处理实验室中的 ALSA、缓冲区、I2S、Codec 和硬件数据流细节。
- 保留必要的模块名称和简短作用说明，使场景链路自身完整可读。

## 场景范围

### 个人终端

展示用户使用笔记本或手机进行近讲会议。画面包含用户、内置麦克风、扬声器、远端参会者和扬声器到麦克风的回声路径。

- 关键技术：AEC、双讲检测、NS/ANR、AGC、耳机模式。
- 体验风险：对方听到回声、键盘噪声、输入削波、打断对方时语音被压制。
- 观察指标：ERLE、端到端延迟、输入峰值、双讲保持能力。
- 排查顺序：确认播放参考进入 AEC，检查参考与采集对齐，再检查扬声器音量及处理强度。

### 多人会议室

展示会议桌、多个说话人、远场麦克风阵列、扬声器和远端参会者。声学路径应表达不同说话距离、房间反射和扬声器回采。

- 关键技术：麦克风阵列、波束拾音、AEC、去混响、多人语音处理。
- 体验风险：远端说话人过小、波束方向错误、混响拖尾、多人同时说话不清楚。
- 观察指标：拾音距离、混响时间、阵列方向、远近说话电平差。
- 排查顺序：先检查原始多麦输入和通道一致性，再检查声源方向与波束，最后检查 AEC 和去混响。

### 弱网会议

展示本端与远端之间不稳定的网络通道，突出数据包抖动、丢包和恢复，不把网络问题误画成声学问题。

- 关键技术：Opus、RTP、FEC、Jitter Buffer、PLC、自适应码率。
- 体验风险：卡顿、断音、机器人音、延迟逐渐增大。
- 观察指标：丢包率、网络抖动、往返时延、缓冲深度、PLC 触发率。
- 排查顺序：先区分采集异常与网络异常，再检查丢包和抖动，最后调整缓冲、FEC 与码率策略。

### 实时字幕

展示增强后的 PCM 从会议上行链路分出旁路，进入流式识别、增量字幕和可选翻译。字幕链路不应被画成音频播放链路的一部分。

- 关键技术：流式 ASR、增量解码、端点检测、字幕稳定、可选翻译。
- 体验风险：首字出现慢、字幕反复改写、最终结果延迟、嘈杂环境识别错误。
- 观察指标：首字延迟、最终结果延迟、字错率、字幕修订次数。
- 排查顺序：先确认增强后音频质量，再区分网络与推理延迟，最后检查端点检测和字幕稳定策略。

## 页面结构

页面从上至下分为五层：

1. 场景切换：`个人终端 / 多人会议室 / 弱网会议 / 实时字幕`。
2. 场景画面：用响应式 SVG 表达人物、设备、声学路径或网络路径。
3. 当前体验：说明用户行为、正常结果和主要风险。
4. 场景链路：仅展示当前场景相关的精简流程，节点与场景画面使用一致的语义颜色。
5. 工程信息：展示当前场景的关键模块、可观察指标和按顺序排列的排查建议。

原有独立的模块说明网格及“回声大、听不清、字幕慢”问题卡片不再重复显示，其有效内容合并进四个场景。

## 交互与状态

- 默认打开“个人终端”。
- 场景按钮使用可访问的选中状态，支持键盘操作。
- 单一 `activeScenario` 状态驱动画面、体验、链路和工程信息，防止不同区域内容不一致。
- 切换场景不产生音频播放，也不引入无助于核心概念的参数滑块。
- 保持现有中英文切换；所有新增文字来自同一场景配置。
- 小屏页面保持单列，宽 SVG 放入明确标注的横向滚动区域，不截断文字。

## 组件设计

保留 `MeetingCommunicationLab` 的外部接口和现有应用路由。组件内部拆分为职责清晰的展示单元：

- 场景配置：保存双语标题、体验、风险、链路节点、指标和排查步骤。
- 场景选择器：只负责切换 `activeScenario`。
- 场景图：根据场景 ID 渲染对应 SVG，不承载解释长文。
- 场景链路：渲染当前场景的流程节点和方向。
- 工程信息区：渲染关键模块、指标和排查步骤。

具体拆分可在不改变行为的前提下保持在同一文件或提取子组件，优先控制组件可读性，不进行无关重构。

## 视觉规则

- 延续现有页面颜色、卡片边界、圆角和字体层级。
- 场景图是主要视觉区域，不嵌套进多层装饰卡片。
- 采集、处理、网络、播放和识别使用稳定且可区分的低饱和度颜色。
- 路径必须使用箭头和标签说明方向；回声路径、网络路径、字幕旁路不可仅依靠颜色区分。
- 所有 SVG 文本在桌面和移动端不得重叠或超出节点。

更新 `src/App.test.tsx` 中会议与通信实验室的测试，至少验证：

- 详情弹窗仍能打开独立实验室。
- 四个场景按钮均存在，默认显示个人终端。
- 切换到多人会议室后显示麦克风阵列和远场相关内容，不保留个人终端的独占内容。
- 切换到弱网会议后显示 Opus、Jitter Buffer、PLC 及网络指标。
- 切换到实时字幕后显示流式 ASR、首字延迟及字幕链路。
- 中文和英文界面的关键标题正常显示。
- 页面返回知识库功能保持正常。

实现完成后运行：

```bash
npm test -- --run src/App.test.tsx
npm run build
git diff --check
```

同时在桌面和移动视口进行页面检查，确认 SVG 非空、场景切换正确、横向滚动区域可用、文字无重叠，并确认本地 Vite 服务仍可访问。
